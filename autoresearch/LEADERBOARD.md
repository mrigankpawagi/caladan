## w4b: Lookups and queries with one shared deadline, arriving in bursts

[workloads/w4b-bursty-shared-deadline.json](workloads/w4b-bursty-shared-deadline.json). The same key-value front end as w3: quick lookups and ten-times-longer queries are both HIGH with one shared 100 us deadline, batch is NORMAL and bulk scans are LOW. Now the traffic arrives in bursts: for the first quarter of every millisecond requests come twice as fast as in the rest of it, so the server is briefly overloaded and then catches up. ## w5: Quick-looking puts that sometimes flush, arriving in bursts

The server marks them HIGH with the shared 100 us deadline and an expected run time of 1 us, because most puts only append to an in-memory log.
